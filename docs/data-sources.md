# Бесплатный сбор данных CS2

Проверено 27 сентября 2026 года. Это исследование: сборщик и интеграции ещё не реализованы.
Стоимость ниже относится к доступу к данным, а не к хостингу и генерации AI-текстов.

## Вывод

Для прототипа стоит проверить KashRock Sandbox: он заявляет бесплатный доступ к матчам CS2.
Для исследования рейтингов можно отдельно использовать публичные файлы Valve.
Полностью проверенного бесплатного источника, который одновременно закрывает актуальное расписание,
глубокую историю, статистику карт и коэффициенты всех букмекеров из макета, не найдено.

KashRock пока кандидат: реальные ответы с ключом, покрытие турниров и условия использования
данных в нашем боте не проверены. Нельзя считать обещания на странице тарифа проверенной интеграцией.

Публичная доступность источника сама по себе не подтверждает право перепубликовывать его данные в боте.

## Что удалось проверить непосредственно

Публичные файлы Valve прочитаны без ключа через HTTP. Проверенный снимок рейтинга —
[7 сентября 2026 года](https://github.com/ValveSoftware/counter-strike_regional_standings/blob/main/live/2026/standings_global_2026_09_07.md).
В деталях Spirit есть даты матчей, соперники, победа/поражение и составы.
Нет достаточных полей для расписания, подробного разбора карт и статистики игроков.
Снимок уже отстаёт от даты исследования; его нельзя выдавать за сегодняшние данные.

В каталоге `data` обнаружен только `matchdata_sample_20230829.json` — старый образец 2023 года.
Это не постоянно обновляемая выгрузка CS2. GitHub API не определил лицензию репозитория;
не следует представлять его как готовый лицензированный коммерческий фид.
Идентификаторы матчей в рейтинговых снимках нельзя считать стабильными между версиями без проверки.

KashRock проверен по официальным страницам, без регистрации и запросов с API-ключом.
Страница [условий](https://www.kashrock.com/legal?tab=terms) не отдала читаемый текст через исследовательский инструмент.
Условия хранения, публикации и использования для прогнозов остаются открытым вопросом.

## Какие данные собирать сначала

Для первого этапа нужны команды, расписание и результаты серий:

- ID матча и команд у источника, названия, турнир, BO1/BO3/BO5.
- Начало в UTC, статус: запланирован, идёт, завершён, перенесён или отменён.
- Итоговый счёт серии и победитель; результаты отдельных карт — только если источник их отдаёт.
- Состав на момент матча, если доступен. Текущий состав не подставлять в старые матчи.
- Источник, время получения и оригинальный ответ для проверки ошибок преобразования.

На этих данных можно вычислять последние пять результатов и личные встречи в доступном периоде.
Если история ограничена 30 днями, нельзя обещать статистику личных встреч за полгода.
ADR, K/D, veto и подробности карт добавлять после подтверждения их доступности.
Отсутствующее значение хранить как `null`, а не как ноль.

## Простая реализация

Достаточно `httpx`, который уже установлен, и встроенного `sqlite3`:

```text
источник → сборщик → data/matches.sqlite3 → Telegram-бот
```

Предлагаемые файлы, создавать их заранее не требуется:

- `src/integrations/esports.py` — запросы к выбранному источнику.
- `src/services/collect.py` — получение, преобразование и обновление данных.
- `src/storage.py` — несколько SQL-запросов к SQLite.

Для начала достаточно таблиц `teams`, `matches`, `raw_responses`.
Для матчей использовать уникальность `(source, source_match_id)` после проверки стабильности ID.
Повторный сбор обновляет существующую запись. Название команды не использовать как идентификатор.
Оригинальные ответы сохранять при изменении содержимого, чтобы не копить одинаковый JSON.
Срок хранения согласовать с условиями выбранного API.

Все пользователи читают общую базу. Нажатие кнопки в Telegram не должно расходовать запрос к поставщику.
Сборщик запускается по расписанию на той же машине; для этого объёма отдельная очередь задач не нужна.
Нужны таймаут, ограниченные повторы при временной ошибке и пауза по `Retry-After` при HTTP 429.
Ошибка источника не должна стирать сохранённые матчи. В боте показывать время обновления.

Пример бюджета для лимита 500 запросов в день:

| Операция | Частота | Запросов в сутки |
| --- | --- | --- |
| Ближайшие матчи | Раз в 15 минут | 96 |
| Недавние результаты | Раз в 30 минут | 48 |
| Остаток на детали, страницы и повторы | По необходимости | 356 |

Это расчёт при одной странице на обновление, а не подтверждённый расход KashRock.
Пагинация, детали каждого матча и первичная загрузка истории расходуют отдельные запросы.
Лимит должен контролироваться сборщиком; перед матчем частоту можно повысить в пределах остатка.

## Проверка перед выбором источника

На бесплатном ключе проверить 20–30 матчей из нескольких нужных турниров:

1. Есть ли матчи до старта, результаты после окончания, BO-формат и постоянные ID.
2. Совпадают ли время, соперники и счёт с опубликованными данными организаторов.
3. Как быстро отражаются переносы, отмены и завершение.
4. Какие поля реально доступны бесплатно: карты, составы, история; сколько страниц и запросов требуется.
5. Разрешены ли накопление истории и использование данных в нашем Telegram-боте.

Затем загрузить доступную историю и начать ежедневное пополнение.
Первые критерии готовности: повторный запуск не создаёт дубликаты, перенос обновляет матч,
результат сохраняется, сбой API оставляет последнюю рабочую версию данных.

## Прогнозы и коэффициенты

Сначала получить надёжную базу и простой ориентир качества — например, рейтинг Elo и форму команд.
Проверять прогнозы на более поздних матчах, используя только информацию, доступную до их начала.
Не использовать сегодняшний рейтинг или состав для оценки прогноза на прошлый матч.
Сохранять прогноз и входные данные до начала игры, результат добавлять после завершения.

AI-текст может объяснять посчитанные показатели. Проценты победы и статистика не должны браться из памяти LLM.
Бесплатный сбор данных не означает бесплатную работу внешнего AI API.

Коэффициенты требуют отдельного источника. Бесплатный доступ ко всем шести букмекерам из Figma не подтверждён.
Для первой версии можно показывать разбор без коэффициентов, а бонусные предложения обновлять вручную.
Позже хранить коэффициенты отдельными снимками: матч, букмекер, рынок, исход, значение и время получения.
Партнёрские ссылки и условия фрибетов не заменяют поток актуальных коэффициентов.
