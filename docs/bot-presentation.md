## Поведение

- В списке матчей доступны «По популярности» и «По времени». По умолчанию — популярность; выбор сохраняется в `data/users.json`. Переключение возвращает на первую страницу. LIVE всегда перед прематчем.
- Популярность — приближение через рейтинг команд, а не измеренная аудитория. Для CS2 сначала используется лучший ранг участника в последнем снимке Valve VRS не старше 45 дней, затем ранг соперника, число разных источников и время. В серверном релизе `20261014-012100` для Dota 2 и команд без рейтинга используются число источников и время; локальное обновление ниже добавляет рейтинг Dota 2. Новых сетевых запросов при открытии списка нет.
- Экран коэффициентов выделяет максимум на команду, выбранную AI, и перечисляет всех букмекеров с этим максимумом. Кнопки сортируются по этому исходу. Закрытые ставки не заменяются рекомендацией противоположного исхода.
- Фаворит относится к конкретной карточке прогноза. Срок — 15 минут для прематча и 2 минуты для LIVE. Смена участников, порядка команд, статуса, турнира, времени или формата матча отменяет привязку. Свежесть самих котировок по-прежнему проверяет `Matches`.
- При отсутствии AI, статистики, вероятности выше 50% или актуальной карточки показываются оба исхода без выделенного фаворита. Данные о фаворите сохраняются между перезапусками; до 30 карточек на пользователя.
- `/bonus` и callback `bonus` открывают отдельный экран. Нет опубликованных предложений — показывается понятное пустое состояние. Команда больше не дублирует `/askbetty`.

## Обновление Dota 2 после релиза — пока локально

- Основной источник — [OpenDota `/teams`](https://docs.opendota.com/): из первой страницы API (до 1000 записей) берутся команды с положительным рейтингом и матчем за последние 90 дней. Места вычисляются по рейтингу среди этой активной выборки. Неоднозначные одинаковые названия исключаются.
- Резервный — [CyberScore](https://cyberscore.live/en/teams/): публичный топ-20 и дата публикации. Пагинация и закрытый API не используются; сборщик проверяет `robots.txt` и соблюдает задержку. Рейтинг старше 45 дней отклоняется.
- Оба сборщика работают независимо в процессе `collector`. Успешное обновление раз в сутки; ошибки увеличивают паузу, HTTP 403 — минимум сутки, `Retry-After` соблюдается. Ключи и новые зависимости не нужны.
- Файлы состояния: `data/dota_rankings/opendota.json` и `data/dota_rankings/cyberscore.json`. Кеш и пауза сохраняются при перезапуске. Пустой/невалидный ответ не заменяет рабочий снимок.
- Выбор: исправный свежий OpenDota → исправный свежий CyberScore → пригодный кеш источника с ошибкой → число букмекеров и время. Возраст загрузки не более 72 часов. После восстановления основной источник возвращается автоматически. Баллы и места разных поставщиков не смешиваются в одной сортировке.
- В списке Dota 2 указан выбранный источник. Для отсутствующих в нём команд остаётся порядок по числу букмекеров и времени; LIVE всегда первыми. Это спортивный рейтинг, не измерение аудитории. Данные не добавлены как новый фактор AI-прогноза.
- В `/status` добавлены `OpenDota · Dota 2`, `CyberScore · Dota 2`, `Рейтинг Dota 2`: состояние, время обновления, число пригодных команд, ошибки, пауза и выбранный источник. Общий монитор уведомляет модераторов об ошибке, ограничении доступа/лимите, устаревании и восстановлении без повторов одинакового состояния, включая перезапуск.
- Флаги `DOTA_OPENDOTA_ENABLED` и `DOTA_CYBERSCORE_ENABLED` по умолчанию `true`; отключение действует и на сбор, и на выбор рейтинга. Длинные отчёты и алерты разделяются на сообщения в пределах лимита Telegram.

14 октября оба настоящих сборщика проверены в отдельном временном каталоге, без запуска Telegram polling и без отправки сообщений: HTTP 200, 38 активных команд OpenDota, 20 команд CyberScore (публикация 13 октября). Парсеры проверены также на сохранённых фрагментах реальных ответов в `tests/fixtures/dota_rankings/`. Полный набор unit-тестов после обновления: 199 проверок; Ruff и `git diff --check` без ошибок. Сервер этим обновлением ещё не менялся.

## Партнёрские предложения

`BONUS_OFFERS` в `.env` — JSON-массив, максимум шесть записей. По умолчанию `[]`. Меньший `priority` показывается выше; коэффициенты на этот порядок не влияют. Публикуются только записи с `enabled: true`. Допустимые `bookmaker`: `pari`, `fonbet`, `marathon`, `winline`, `leon`, `betboom`.

Пример формата, **не реальное предложение**:

```dotenv
BONUS_OFFERS='[{"bookmaker":"pari","priority":10,"description":"Заменить согласованными условиями и сроком действия","url":"https://example.com/approved-offer","enabled":false}]'
```

Перед включением заменить пример фактическими условиями, партнёрской HTTPS-ссылкой и согласованным приоритетом. `description` — обычный текст до 300 символов, HTML экранируется. URL с логином/паролем или без HTTPS не принимается. После изменения `.env` требуется пересоздать контейнер `bot`, чтобы перечитать окружение; использовать skill `betty-deploy`. Обычный `docker compose restart` окружение не обновляет.

В переписке нет финального порядка всех букмекеров и полного комплекта условий/ссылок. Внутренние CPA и KPI не превращены в обещания пользователям.

## Эмодзи

- `assets/custom-emoji.json`: 47 сопоставлений организаций CS2 и все шесть букмекеров. Алиасы нормализуются через `team_key`; у неизвестной команды остаётся имя и доступный флаг страны. Для Dota 2 словарь CS2 не применяется.
- `assets/emoji-packs.json`: каталог 640 ID. Семь паков выгружены полностью; для PARI и Марафона сохранены конкретные присланные эмодзи. Каталог включает портреты игроков — наличие ID само по себе не означает, что это логотип команды.
- Источник — присланные Динаром паки и сообщения от 6 октября. Выгрузка ID также присутствует в чате с `@Emoji_ID_Extractor_bot`; метаданные ID проверены через официальный `getCustomEmojiStickers`, паки — через `getStickerSet`. Новых сообщений Динару и экстрактору не отправлялось.
- Логотипы команд выводятся в шапке разбора, букмекеров — в тексте коэффициентов, бонусах и кнопках букмекеров. В текстах используются `<tg-emoji>`, в кнопках — `icon_custom_emoji_id`.
- `CUSTOM_EMOJI_ENABLED=false` выключает кастомные логотипы, сохраняя названия и кнопки. При явном отказе Telegram с ошибкой emoji отправка повторяется без логотипов; посторонние ошибки не скрываются.
- По [Telegram Bot API](https://core.telegram.org/bots/api#html-style), для таких сообщений бот должен иметь дополнительный username с Fragment либо владельца с Telegram Premium. Код и ресурсы опубликованы, `CUSTOM_EMOJI_ENABLED=true`. Визуальное отображение в клиенте Telegram пока не проверялось: тестовые сообщения пользователям не отправлялись. Согласование брендбука с партнёрами остаётся отдельным пунктом Динара.

## Исследование статистики карт и раундов

Автоматический источник не подключён; `winning_round_margin` и `active_maps` по-прежнему не заполняются штатным сборщиком. Эти факторы остаются скрытыми, без подставных значений.

- [PandaScore Plan reference](https://developers.pandascore.co/docs/plan-reference): расписание и результаты серий доступны бесплатно; данные игр внутри матча и командная статистика требуют Historical, подробные раунды CS2 — Basic Live. Для среднего запаса победы достаточно конечного счёта карт, подробные события раундов не обязательны.
- [Valve VRS](https://github.com/ValveSoftware/counter-strike_regional_standings): в `data/` найден демонстрационный набор 2023 года, не текущая база результатов карт. Рейтинги уже используются отдельно.
- HLTV: обычный запрос к `robots.txt` получил HTTP 403 с проверкой Cloudflare. Обход не реализовывался.
- [bo3.gg](https://bo3.gg/teams/spirit/matches): сайт публикует результаты, но обычный HTTP-запрос вернул оболочку приложения без таблицы матчей. Его [robots.txt](https://bo3.gg/robots.txt) исключает `/api/` и ряд фильтрованных страниц. Доступный устойчивый способ регулярного сбора не подтверждён; это не утверждение, что бесплатного источника вообще не существует.

Для закрытия этих двух пунктов нужны доступный источник и определение периода/минимальной выборки для «активной карты». Новые платные подписки не оформлялись.
