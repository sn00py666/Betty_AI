# Betty AI Bot

Telegram-бот: реальные матчи CS2 / Dota 2, сравнение коэффициентов и AI-комментарии через OpenRouter.
Интерфейс следует [сценарию Figma](https://www.figma.com/design/BHxPEFEcG5SX6PH8jHf89P/?node-id=0-1).

## Запуск

```bash
cp .env.example .env  # Только если своего .env ещё нет
uv sync --locked
uv run python src/collect.py --watch
# В другом терминале:
uv run python src/main.py
# Для личных алертов, в третьем терминале:
uv run python src/monitor.py
```

Заполните `TELEGRAM_BOT_TOKEN`, `AI_API_KEY` и `PANDASCORE_API_KEY`. Модель: `google/gemini-2.5-flash-lite`.
Без AI-ключа работает сравнение котировок. Запускайте один бот на токен и один сборщик на каталог данных.

## Сценарий

- `/start` → дисциплина → свежие матчи, по 5 на страницу, стрелки листают то же сообщение → разбор → ссылки букмекеров через 3 секунды.
- Карточка показывает время по Москве, вероятность победы сверху, факторы и короткий AI-вывод.
  Коэффициенты и лучшие цены отправляются отдельным сообщением.
- `/askbetty` и `/bonus` открывают список матчей. Партнёрских ссылок и обещаний бонусов нет.
- `/info` объясняет источники и ограничения.
- `/notifications` включает подборку в 12:00 и фаворита рынка в 18:00 МСК. По умолчанию выключено.
- «Напомнить» в карточке — уведомление за 30 минут, если расписание и свежий матч доступны.
- `/donate 50` — внутренний донат Stars; ответ после оплаты: `Ок, принят`.

В выборе матча сначала идут live-события, затем предстоящие по времени начала; события без времени —
в конце своей группы. Названия CS2 берутся из локального словаря рейтинга HLTV от 05.10.2026,
с исключениями NAVI и NIP. Разные варианты источников приводятся к эталону до сопоставления матчей.
Словарь находится в `src/services/team_names.py`; неизвестные команды и названия Dota 2 сохраняются.
Отчёт удаляет ссылки из AI-комментария и предотвращает автоссылки Telegram в названиях с точкой.

PandaScore добавляет последние 5 доступных игр команды, очные встречи в выборке за 180 дней и
результаты текущего этапа турнира (когда событие сопоставлено по командам и времени).
Для команды берётся до 100 последних завершённых матчей; технические победы исключаются.
Бесплатный сборщик Valve VRS добавляет текущий глобальный рейтинг и результаты против топ-10 Valve.
Индекс проверяется раз в сутки; хранятся восемь последних снимков. Для исторического матча берётся
последний снимок, опубликованный до дня игры, не старше 45 дней. Повторяющиеся названия составов
исключаются. Valve VRS и HLTV — разные рейтинги; источник указывается в карточке.
Карты и раундовый счёт этот источник не добавляет.
Числовые факты и итог по факторам в тексте формирует код. AI получает статистику без котировок,
выбирает исход и возвращает приблизительную вероятность победы (не калиброванную модель).
Итоговый абзац объясняет перевес в 2–3 предложениях; общую форму можно описывать по последним
результатам, приводя число побед обеих команд. Модель получает последовательность матчей и готовое
сравнение долей побед (при минимум трёх играх у каждой команды). Эти данные не описывают весь сезон.
Упоминание сезонной формы допускается как предварительное впечатление с оговоркой
«судя по последним матчам» и результатами обеих команд, если последние результаты различаются.
При противоречии общей формы и результатов турнира промпт требует назвать оба аргумента;
если других аргументов нет — не выбирать фаворита. Для неполных данных промпт задаёт
редакционный предел 51–60%, который не является калибровкой вероятности.
Если единственный направленный критерий — результаты турнира — противоречит общей форме,
код заменяет ответ модели кратким сравнением обоих показателей без выбранного победителя.
Карточка показывает только подтверждённые критерии: последние результаты, форму против топ-10,
средний запас раундов в выигранных картах, активный пул карт, результаты этапа и личные встречи.
Последние результаты учитываются в строке-итоге. Менее трёх очных встреч считаются нейтральным фактором.
Критерии без показателей скрыты вместе со счётчиком пропусков; AI-комментарий не перечисляет пропуски.
Текущий сборщик не получает рейтинг топ-10, раундовые результаты и маппул.
Для подключения этих показателей предусмотрены поля статистики `top10` (`games`, `wins`),
`winning_round_margin` и `active_maps` (список уникальных названий карт).
Флаги выводятся из двухбуквенного кода страны источника, без догадок по названию команды.
Для Dota 2 раундовые показатели и маппул не выводятся.
Если статистики нет, прогноз и процент не генерируются. Если AI недоступен, остаются факторы.

`data/pandascore.json` хранит общий для всех пользователей дисковый кеш: список до 100 предстоящих матчей
на дисциплину на час, историю каждой команды на 6 часов. Запросы только при открытии разбора;
повторный разбор и другой матч той же команды переиспользуют кеш. Нет фонового обхода всех команд.
Сохраняются только необходимые поля, максимум 200 ответов. Пустой ответ тоже кешируется.
`PANDASCORE_DAILY_LIMIT=100` — наш дополнительный предел запросов за сутки UTC, включая ошибки.
Счётчик и паузы переживают перезапуск. При 429 — пауза минимум час с учётом Retry-After,
при 401/403 — час, при сетевом сбое — 5 минут. Просроченная статистика не выдаётся за свежую.


Закрытые и устаревшие котировки не участвуют в сравнении. При сбое AI остаётся числовой разбор.
Одинаковые входные данные кешируются на диске (до 500 ответов). `AI_DAILY_LIMIT=500` ограничивает число
обращений к провайдеру за сутки UTC; попытки с ошибками тоже учитываются. Запрос ограничен 700 выходными
токенами и таймаутом. Настройки меняются в `.env`, секреты не коммитятся.
`AI_TEMPERATURE=0.35` задаёт вариативность текста; промпт и температура входят в ключ кеша,
поэтому их изменение не переиспользует старые ответы.
Для повторного сравнения: `.venv/bin/python scripts/compare_forecast_prompts.py`.
Скрипт делает 20 запросов на пяти вымышленных сценариях при температурах 0.35 и 0.65,
учитывает дневной лимит и сохраняет ответы в `data/prompt_experiments.json`.
Можно задать `--temperatures`, `--repeats`, `--baseline` (файл с прежним промптом) и `--output`.

Gemini Flash Lite выбрана после проб Gemini, Qwen 3 32B и Mistral Small 3.2: в небольшом тесте Gemini
ответила быстрее и осторожнее. Это проверка текста и формата, не точности прогнозов.

## Код и проверки

- `handlers/menu.py`, `keyboards/menu.py`, `content.py` — экраны и переходы.
- `services/matches.py` — свежесть, сопоставление событий и вероятность из линии.
- `services/statistics.py` — PandaScore, кеш, квота и подсчёт результатов.
- `services/rankings.py` — загрузка Valve VRS и сопоставление исторического топ-10.
- `services/monitoring.py`, `services/health.py`, `monitor.py`, `handlers/admin.py` — состояние и личные алерты.
- `services/ai.py`, `services/analysis.py` — запрос к модели и оформление ответа.
- `services/notifications.py`, `services/users.py` — подписки, напоминания, JSON-хранилище.
- `collect.py`, `integrations/` — сбор и разбор ответов букмекеров.

Все пути выше относительно `src/`. Данные лежат в `data/`, рассчитаны на один процесс бота.

```bash
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

Тесты не отправляют сообщения, платежи или запросы к букмекерам/AI.

## Сбор матчей и коэффициентов

### Запуск в Docker на Linux x86_64

Нужны Docker с Compose и `.env` с `TELEGRAM_BOT_TOKEN` рядом с `compose.yaml`.
Образ устанавливает Chrome; для сборщика используется виртуальный экран Xvfb.
Бот, сборщик и монитор запускаются раздельно, без открытых сетевых портов и без root внутри контейнера.

```bash
mkdir -p data
sudo chown -R 10001:10001 data
docker compose build
docker compose up -d
docker compose logs --tail=50
```

`data/` сохраняется на хосте между перезапусками. `.env` не попадает в образ или Git.
Перед запуском бота остановите другой экземпляр с тем же токеном, чтобы не конфликтовал Telegram polling.
Логи контейнеров ограничены по размеру; историю `data/odds/*/history.jsonl` нужно контролировать отдельно.

Для разового сбора при остановленном сервисе `collector`:

```bash
docker compose run --rm collector xvfb-run -a python src/collect.py leon betboom
```

### Мониторинг

В `.env` задайте `ADMIN_USER_IDS=[123456789]` с числовыми Telegram ID. Каждый модератор должен
открыть личный чат с ботом и отправить `/start`; `/myid` показывает ID. `/status` доступен только
указанным модераторам в личном чате и читает локальные файлы без запросов к поставщикам.

Отчёт показывает процессы бота и сборщика, шесть букмекеров, PandaScore, OpenRouter AI, Valve VRS
и свободное место. Для источников указаны обновление, число матчей, ошибки и паузы;
для API — успешный запрос и расход дневной квоты. HTTP 401/403/451 означают ограничение доступа,
а не доказанный бан. HTTP 429 и исчерпание внутренней квоты отмечаются как лимит запросов.

Отдельный сервис `monitor` проверяет состояние каждые 30 секунд. Он отправляет личное сообщение
при появлении проблемы, изменении категории ошибки и восстановлении. Одинаковый сбой не повторяет
алерт; состояние доставки сохраняется в `data/monitor.json` и переживает перезапуск.
Если Telegram недоступен, сообщение повторяется не ранее чем через пять минут.
Отсутствие сигнала процесса более трёх минут и устаревание снимка букмекера более 65 минут
считаются проблемой; при запуске есть две минуты ожидания. PandaScore и AI вызываются по запросу,
поэтому отсутствие новых запросов само по себе не означает сбой.
Монитор может сообщить об остановке бота, пока сам сервер и Telegram доступны.

Состояния API и сигналы процессов лежат в `data/health/`; рейтинг — в `data/valve.json`.
Монитор не возобновляет остановленные источники. После исправления причины используйте порядок
ручного возобновления ниже, сохранив срок следующего запроса.

### Источники и формат

Подключены **Фонбет, Марафон, PARI, Winline, Леон и BetBoom**, для CS2 и Dota 2.
Собираем П1/П2 на победителя всего матча. Котировки отдельных карт, дуэли игроков и рынки
с ничьей не смешиваются с двухисходным победителем серии. Закрытая цена сохраняется как `null`.

Фонбет и PARI отдают JSON общей линии; Марафон — HTML страницы киберспорта.
Winline, Леон и BetBoom открывают по две страницы в отдельном Chrome: CS2 и Dota 2.
Сборщик ждёт загрузки линии, раскрывает турниры BetBoom и прокручивает список до конца.
Повторяющиеся карточки из снимков объединяются по ID; неограниченного обхода страниц нет.
Если список не закончился за 30 прокруток, источник останавливается для проверки.

Время приводится к UTC: у Марафона часовой пояс берётся из страницы, у браузерных источников
задан `Europe/Moscow`. Леон показывает отсчёт до матча с точностью до минуты;
сопоставление допускает расхождение старта до 5 минут. Известные варианты названий команд
сведены в небольшой словарь. Без даты или при неоднозначном совпадении матчи не объединяются.
У каждого снимка страницы сохраняется своё время получения: прокрутка не продлевает свежесть старых цен.

Леон и BetBoom используют Chrome с графическим сеансом (на сервере — Xvfb), Winline — headless Chrome.
Личный профиль, авторизация и расширения не используются. BetBoom пока сохраняет ссылку на раздел
дисциплины: у карточек нет `href`. Остальные источники сохраняют ссылки на матч.
CSS-классы могут измениться; исходные ответы сохраняются для отладки в `response.gz`.
Для браузерных источников внутри архива — JSON со страницами HTML и временем их получения.

Разовый сбор, без Telegram-токена:

```bash
uv sync --locked
uv run python src/collect.py
```

Только новые источники:

```bash
uv run python src/collect.py leon betboom
```

Только выбранный источник или длительная работа в терминале:

```bash
uv run python src/collect.py marathon
uv run python src/collect.py pari winline
uv run python src/collect.py fonbet marathon pari winline --watch
```

Для Winline нужен установленный Google Chrome. Если его нет, установите браузер обычным способом
или командой `uv run playwright install chrome`. На машине разработки используется уже установленный Chrome.
Личный профиль браузера не используется. Сам сборщик ничего не устанавливает.

`--watch` работает, пока открыт процесс; остановка — Ctrl+C. В Docker процесс перезапускается автоматически.
Используется файловая блокировка `fcntl`: поддерживаются macOS и Linux, один процесс на общую папку данных.
Не запускайте копии на разных машинах: между ними лимиты не синхронизированы.

В `data/odds/<букмекер>/` сохраняются:

- `latest.json` — последний успешный снимок, время получения и срок актуальности.
- `history.jsonl` — снимки при изменении списка матчей или коэффициентов.
- `response.gz` — последний исходный ответ для отладки.
- `failed-response.gz` — последний ответ, который не удалось разобрать; успешный снимок сохраняется отдельно.
- `state.json` — срок следующего запроса, кеш robots.txt и причина остановки.

Данные исключены из Git. На настроенном сервере история ротируется logrotate; при другом развёртывании настройте ротацию отдельно.
Фонбет и PARI отдают общий ответ линии: фильтрация CS2 и Dota 2 выполняется локально.
В JSON Фонбета и PARI для Dota 2 берутся только серии с указанным BO и без рынка ничьей.
Марафон собирается с одной страницы киберспорта, без обхода всех карточек; полнота линии не гарантирована.
Telegram читает эти снимки; совпадающие события объединяются по дисциплине, командам и точному времени.
Без подтверждённой даты карточки разных букмекеров остаются отдельными.

### Ограничение нагрузки

- Один цикл на источник раз в 30 минут плюс небольшой случайный сдвиг; немедленных повторов нет.
- Для Winline цикл открывает две страницы в одном браузерном сеансе: она делает несколько запросов и подключает WebSocket.
  Изображения, шрифты, медиа и HTTP-запросы к сторонним доменам отключены. Сеанс закрывается после чтения карточек.
- Для Леона и BetBoom сторонние ресурсы не блокируются: они нужны проверке браузера и виджету линии.
  robots.txt проверяется в том же Chrome перед загрузкой линии и кешируется на сутки. Окно закрывается после снимка.
- Пауза записывается на диск до запроса и сохраняется после перезапуска.
- Проверка robots.txt раз в сутки; учитываются запреты и Crawl-delay.
- Между robots.txt и линией, а также страницами дисциплин — минимум 10 секунд. HTTP-сборщики работают последовательно;
  ресурсы внутри Chrome загружаются самим браузером.
- Для HTTP-сборщиков — условные запросы с ETag/Last-Modified, если сервер их предоставляет.
- 429: пауза минимум час с учётом Retry-After; повторные ошибки увеличивают паузу.
- 403, 401, 451 или обнаруженная проверка посетителя останавливают источник до ручной проверки.
  HTTP-сборщики также останавливаются на перенаправлениях; браузерные следуют обычным переходам сайта.
- Таймаут браузера, изменившийся формат или пустая линия запускают повтор через 1, 2, 4 часа и далее
  до суток. Ошибка видна в `/status` и алерте; старый снимок не становится свежим. Успех сбрасывает паузу.
- При сетевой ошибке сохранённые данные остаются, но их `expires_at` не продлевается.

Это осторожные настройки для накопления истории, **не гарантия отсутствия блокировки** и не live-линия.
Каждый live-матч истекает через 60 секунд, прематч — через 30 минут. Следующий цикл через 30 минут:
этого недостаточно для непрерывной выдачи актуальных live-коэффициентов, зато подходит для редких снимков.
Не показывайте просроченный снимок как текущие коэффициенты. Даже свежий снимок может отставать от сайта.
HTTP-заголовки используют постоянный профиль Chrome 154 на macOS: браузерный User-Agent,
Accept-Language с приоритетом русского языка и Accept под HTML или JSON.
User-Agent задан в `src/collect.py`; случайной смены браузера на каждый запрос нет.
В течение запуска один HTTP-клиент повторно использует соединения и cookies, полученные от сайтов;
cookies из личного браузера не читаются и на диск не сохраняются.
Accept-Encoding выбирает httpx по реально поддерживаемым алгоритмам сжатия.
Для HTTP-сборщиков это только заголовки: TLS-отпечаток остаётся у httpx, JavaScript не исполняется.
Winline использует настоящий Chrome с JavaScript, без расширений для скрытия автоматизации.
BetBoom сохраняет собственную анонимную браузерную сессию в `data/browser/betboom.json` (права 600).
При промежуточном HTTP 401 от Qrator сборщик ждёт обычного завершения загрузки страницы до 30 секунд;
продолжает только после успешной навигации и появления публичной линии. CAPTCHA вручную или автоматически
не решается; незавершённая проверка оставляет источник на ручной паузе.
Эффект на блокировки не измерен; профиль не делает сборщик неотличимым от Chrome.
Не используются вход в аккаунт, обход CAPTCHA, смена IP или зеркал.
Правила robots.txt по-прежнему проверяются для BettyAI, независимо от браузерного HTTP-заголовка.
robots.txt не заменяет условия использования данных владельца сайта.

Остановленный источник сам не возобновляет запросы. После устранения причины при выключенном процессе
можно изменить `paused` на `false` в его `state.json`, сохранив `next_request`.
Не удаляйте состояние ради обхода паузы.

Этот ручной режим относится к ограничению доступа, проверке посетителя и запретам robots.txt.
Ошибки загрузки и разбора повторяются автоматически с указанным выше интервалом.
Парсер BetBoom использует идентификаторы матчей, роли элементов и структуру карточек, а не
минифицированные CSS-классы сайта. Сборщик ожидает появления линии до 60 секунд.

Проверки сборщика используют сохранённые фрагменты настоящих ответов и подменённый HTTP:
`uv run pytest tests/unit/test_collect.py`. Они не обращаются к букмекерам.
Фрагменты PARI (`pari.json`) и Winline (`winline.html`) получены 4 октября 2026 года.
HTML-фикстура Winline содержит live-матчи и дуэль игроков для проверки фильтрации.
