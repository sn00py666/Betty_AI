# Betty AI Bot

Telegram-бот на aiogram с интерфейсом из [Figma](https://www.figma.com/design/BHxPEFEcG5SX6PH8jHf89P/?node-id=0-1).

Сейчас это рабочий сценарий на примерах из макета. Матчи, прогнозы и бонусы помечены как демо: реальный AI, расписание и партнёрские ссылки ещё не подключены.

## Запуск

Из корня проекта:

```bash
uv sync --locked
uv run python src/main.py
```

Токен от @BotFather читается из `TELEGRAM_BOT_TOKEN` в локальном `.env`. Если файла нет, скопируйте `.env.example` и заполните токен. Для запуска другие API-ключи не нужны. Остановка — `Ctrl+C`.

Бот работает через long polling. Запускайте один экземпляр на один токен; JSON-хранилище также рассчитано на один процесс.

## Что работает

- Первый `/start`: приветствие и кнопки CS-2 / Dota 2.
- Повторный `/start`: короткий выбор дисциплины.
- CS-2: четыре матча из макета и кнопка «назад».
- NAVI — FaZe: разбор, через 3 секунды — бонусная картинка с шестью кнопками и реакцией 🔥.
- `/info`: описание из макета и переход к матчам.
- `/bonus`: бонусный экран. Кнопки честно сообщают, что ссылки пока не подключены.
- `/askbetty`: переход к примерам разборов; свободного AI-диалога пока нет.
- Выбранная дисциплина и факт первого запуска сохраняются в `data/users.json`.
- `/donate` и `/donate 50`: ранее добавленный донат в Stars; после оплаты — ровно `Ок, принят`.

Для Dota 2 и трёх матчей без разбора показаны понятные пустые состояния. Дополнительные прогнозы не выдумываются. Пагинации пока нет: в макете всего четыре матча.

## Просмотр уведомлений

В Figma есть пуш за 3 часа до первого матча, вариант с фаворитом дня, напоминание за 30 минут и итог матча. Посмотреть эти экраны можно вручную:

```text

/preview reminder
/preview result
```

Сообщение получит только вызвавший команду пользователь. Автоматического расписания и рассылок сейчас нет — для них нужен источник времени матчей и результатов. Эти команды и `/donate` не добавляются в основное меню из Figma.

```text
src/
├── main.py              # Запуск, меню команд и подключение обработчиков

├── handlers/

│   └── donate.py        # Донат в Stars

├── services/users.py    # Сохранение выбора пользователя в JSON

└── integrations/bookmakers.py # Разбор ответов букмекеров
assets/bonus.png         # Оригинальная картинка из макета
```

Чтобы поменять сообщение, редактируйте `content.py`; кнопку — `keyboards/menu.py`; действие по нажатию — `handlers/menu.py`. Дополнительных фреймворков, ORM, очередей и фонового планировщика нет.

## Проверки

```bash
uv run ruff check .
uv run ruff format --check .
uv run pytest
```

Тесты подменяют Telegram API и не отправляют сообщения или платежи. Команда `/donate` в запущенном боте использует настоящие Stars. История платежей отдельно не хранится; идентификатор успешного платежа выводится в консоль.

Зависимости описаны в `pyproject.toml`, точные версии — в `uv.lock`. Используется Python 3.13.

## Сбор матчей и коэффициентов

### Запуск в Docker на Linux x86_64

Нужны Docker с Compose и `.env` с `TELEGRAM_BOT_TOKEN` рядом с `compose.yaml`.
Образ устанавливает Chrome; для сборщика используется виртуальный экран Xvfb.
Бот и сборщик запускаются раздельно, без открытых сетевых портов и без root внутри контейнера.

```bash
mkdir -p data
sudo chown -R 10001:10001 data
docker compose build
docker compose up -d
docker compose logs --tail=50
```

`data/` сохраняется на хосте между перезапусками. `.env` не попадает в образ или Git.
Перед запуском бота остановите другой экземпляр с тем же токеном, чтобы не конфликтовал Telegram polling.
Логи контейнеров ограничены по размеру; историю `data/odds/*/history.jsonl` нужно контролировать отдельно.

Для разового сбора при остановленном сервисе `collector`:

```bash
docker compose run --rm collector xvfb-run -a python src/collect.py leon betboom
```

### Источники и формат

Проверено 4 октября 2026 года. Подключены **Фонбет, Марафон, PARI, Winline, Леон и BetBoom**.
Фонбет, Марафон и PARI собирают прематч CS2: команды, турнир и П1/П2 на победителя всей серии.
PARI использует проверенный `/events/listBase`, формат совпадает с Фонбетом.
Winline загружает страницу в отдельном Chrome через Playwright и читает видимые карточки.
У каждой записи есть `status`: `prematch` или `live`; котировки карты и дуэли игроков исключаются.
Проверочный запуск новых источников сохранил 38 матчей PARI и 4 live-матча Winline.
Winline пока покрывает только отрисованные карточки: полнота прематч-линии не подтверждена.
Точное время старта и BO-формат Winline не извлекаются; `starts_at` и `best_of` равны `null`.
Для live-событий текст текущей карты сохраняется в `live_period`, а не как время начала.
У Марафона точное время UTC есть только для части матчей; для остальных сохранена подпись даты
из страницы, а `starts_at` равен `null`. Сборщик не угадывает часовой пояс и год.

Леон и BetBoom открывают **видимое окно отдельного Chrome** и ждут появления линии после JavaScript/WebSocket.
Нужны установленный Chrome и графический сеанс; личный профиль, авторизация и расширения не используются.
Проверочный запуск сохранил **37 матчей Леона (33 прематч + 4 live)** и **4 live-матча BetBoom**.
Леон читает карточки со страницы https://leon.ru/esports/cs2, включая свёрнутые турниры, присутствующие в DOM.
BetBoom читает только live CS2 с https://betboom.ru/esport/live/counter-strike-2 и только основной рынок «Исход».
Прематч BetBoom и полный обход виртуального списка пока не реализованы: снимок содержит отрисованные карточки.
Закрытая котировка сохраняется как `null`. Точные даты и BO-формат этих двух источников пока не извлекаются.
У BetBoom нет href в карточках: сохраняется ID матча и ссылка на раздел, а не выдуманная ссылка на матч.
Его короткие CSS-классы могут измениться при обновлении сайта; HTML последнего снимка сохраняется для отладки.

Разовый сбор, без Telegram-токена:

```bash
uv sync --locked
uv run python src/collect.py
```

Только новые источники:

```bash
uv run python src/collect.py leon betboom
```

Только выбранный источник или длительная работа в терминале:

```bash
uv run python src/collect.py marathon
uv run python src/collect.py pari winline
uv run python src/collect.py fonbet marathon pari winline --watch
```

Для Winline нужен установленный Google Chrome. Если его нет, установите браузер обычным способом
или командой `uv run playwright install chrome`. На машине разработки используется уже установленный Chrome.
Личный профиль браузера не используется. Сам сборщик ничего не устанавливает.

`--watch` работает, пока открыт процесс; остановка — Ctrl+C. Автозапуск не установлен.
Используется файловая блокировка `fcntl`: поддерживаются macOS и Linux, один процесс на общую папку данных.
Не запускайте копии на разных машинах: между ними лимиты не синхронизированы.

В `data/odds/<букмекер>/` сохраняются:

- `latest.json` — последний успешный снимок, время получения и срок актуальности.
- `history.jsonl` — снимки при изменении списка матчей или коэффициентов.
- `response.gz` — последний исходный ответ для отладки.
- `state.json` — срок следующего запроса, кеш robots.txt и причина остановки.

Данные исключены из Git. История растёт со временем; её удаление или архивирование пока ручное.
Фонбет и PARI отдают общий ответ линии: фильтрация CS2 выполняется локально.
Марафон собирается с одной страницы киберспорта, без обхода всех карточек; полнота линии не гарантирована.
Это отдельный сбор: Telegram-интерфейс пока остаётся демонстрационным, объединение матчей разных БК не реализовано.

### Ограничение нагрузки

- Один цикл на источник раз в 30 минут плюс небольшой случайный сдвиг; немедленных повторов нет.
- Для Winline цикл открывает браузерную страницу: она делает несколько запросов и подключает WebSocket.
  Изображения, шрифты, медиа и HTTP-запросы к сторонним доменам отключены. Сеанс закрывается после чтения карточек.
- Для Леона и BetBoom сторонние ресурсы не блокируются: они нужны проверке браузера и виджету линии.
  robots.txt проверяется в том же Chrome перед загрузкой линии и кешируется на сутки. Окно закрывается после снимка.
- Пауза записывается на диск до запроса и сохраняется после перезапуска.
- Проверка robots.txt раз в сутки; учитываются запреты и Crawl-delay.
- Между robots.txt и линией — минимум 10 секунд. HTTP-сборщики работают последовательно;
  ресурсы внутри Chrome загружаются самим браузером.
- Для HTTP-сборщиков — условные запросы с ETag/Last-Modified, если сервер их предоставляет.
- 429: пауза минимум час с учётом Retry-After; повторные ошибки увеличивают паузу.
- 403, 401, 451 или обнаруженная проверка посетителя останавливают источник до ручной проверки.
  HTTP-сборщики также останавливаются на перенаправлениях; браузерные следуют обычным переходам сайта.
- Изменившийся формат или пустая линия также останавливают источник; старый снимок не становится свежим.
- При сетевой ошибке сохранённые данные остаются, но их `expires_at` не продлевается.

Это осторожные настройки для накопления истории, **не гарантия отсутствия блокировки** и не live-линия.
Любой снимок с live-матчами истекает через 60 секунд, хотя следующий цикл будет только через 30 минут:
этого недостаточно для непрерывной выдачи актуальных live-коэффициентов, зато подходит для редких снимков.
Не показывайте просроченный снимок как текущие коэффициенты. Даже свежий снимок может отставать от сайта.
HTTP-заголовки используют постоянный профиль Chrome 154 на macOS: браузерный User-Agent,
Accept-Language с приоритетом русского языка и Accept под HTML или JSON.
User-Agent задан в `src/collect.py`; случайной смены браузера на каждый запрос нет.
В течение запуска один HTTP-клиент повторно использует соединения и cookies, полученные от сайтов;
cookies из личного браузера не читаются и на диск не сохраняются.
Accept-Encoding выбирает httpx по реально поддерживаемым алгоритмам сжатия.
Для HTTP-сборщиков это только заголовки: TLS-отпечаток остаётся у httpx, JavaScript не исполняется.
Winline использует настоящий Chrome с JavaScript, без расширений для скрытия автоматизации.
Эффект на блокировки не измерен; профиль не делает сборщик неотличимым от Chrome.
Не используются вход в аккаунт, обход CAPTCHA, смена IP или зеркал.
Правила robots.txt по-прежнему проверяются для BettyAI, независимо от браузерного HTTP-заголовка.
robots.txt не заменяет условия использования данных владельца сайта.

Остановленный источник сам не возобновляет запросы. После устранения причины при выключенном процессе
можно изменить `paused` на `false` в его `state.json`, сохранив `next_request`.
Не удаляйте состояние ради обхода паузы.

Проверки сборщика используют сохранённые фрагменты настоящих ответов и подменённый HTTP:
`uv run pytest tests/unit/test_collect.py`. Они не обращаются к букмекерам.
Фрагменты PARI (`pari.json`) и Winline (`winline.html`) получены 4 октября 2026 года.
HTML-фикстура Winline содержит live-матчи и дуэль игроков для проверки фильтрации.
